# منظومة المقصد المتكاملة

النظام الإداري والتشغيلي والمالي لشركة **المقصد لإدارة الأملاك والتسويق العقاري**.

مبني على نموذج العمل الفعلي للشركة: **إدارة أصول عقارية لصالح الغير** — ملّاك ومستثمرون
وصناديق ريت — لا التطوير العقاري. لذلك محور النظام هو **المالك**: عقد إدارته، عمولته،
كشف حسابه، وصافي التوريد المستحق له.

---

## ما هو منجَز في هذه المرحلة (المرحلة الأولى)

| الوحدة | الحالة |
|---|---|
| النواة: مستخدمون، أدوار، صلاحيات، سجل تدقيق | ✅ |
| سجل الأصول: محفظة ← عقار ← وحدة | ✅ |
| إدارة المُلاك والمستثمرين وصناديق الريت | ✅ |
| عقود الإدارة: العمولة وسقف الصرف | ✅ |
| المستأجرون وعقود الإيجار | ✅ |
| توليد جدول الفواتير آلياً من العقد | ✅ |
| التحصيل وسندات القبض | ✅ |
| المصروفات والتحميل على المالك أو الشركة | ✅ |
| كشف حساب المالك الآلي + نسخة للطباعة | ✅ |
| توريدات المُلاك | ✅ |
| الوثائق وتنبيهات الانتهاء | ✅ |
| لوحة المعلومات التنفيذية | ✅ |
| **بوابة المالك والمستثمر** | ✅ |

### المعادلة المالية الأساسية
```
المحصّل فعلياً في الفترة
−  المصروفات المعتمدة المحمّلة على المالك
−  عمولة إدارة الأملاك (حسب عقد الإدارة)
=  صافي التوريد المستحق للمالك
```
تُحتسب آلياً على مستوى المالك وعلى مستوى كل عقار على حدة.

**أنواع العمولة المدعومة:** نسبة من المحصّل فعلياً · نسبة من الإيجار المتعاقد · مبلغ شهري ثابت.

## التشغيل

```bash
npm install
cp .env.example .env      # ثم عدّل SESSION_SECRET
npm run setup             # إنشاء قاعدة البيانات + بيانات تجريبية
npm run dev               # http://localhost:3000
```

### حسابات تجريبية (كلمة المرور: `123456`)

| البريد | الدور | يرى |
|---|---|---|
| `admin@almaqsd.co` | مدير النظام | كل شيء |
| `finance@almaqsd.co` | الفريق المالي | المالية والتحصيل والتوريدات |
| `ops@almaqsd.co` | الفريق الإداري | المُلاك والعقارات والعقود |
| `legal@almaqsd.co` | الفريق القانوني | العقود والوثائق |
| `maintenance@almaqsd.co` | فريق الصيانة | العقارات والمصروفات |
| `owner@example.com` | مالك | بوابته فقط |

> **البيانات التجريبية غير حقيقية.** أرقامها تحاكي حجم الشركة المعلن (أصول تتجاوز 600 مليون
> ريال، أكثر من 300 وحدة) لغرض الاختبار، وتُستبدل ببيانات الشركة الفعلية عند الاعتماد.

## البنية التقنية

- **Next.js 15** (App Router) + **React 19** + **TypeScript**
- **Prisma** ORM — SQLite للتطوير، PostgreSQL للإنتاج
- جلسات موقّعة بـ **JWT** في كوكي HttpOnly + **bcrypt**
- **Server Actions** لكل عمليات الكتابة، مع تحقق `zod`
- واجهة عربية RTL بهوية المقصد البصرية (ذهبي `#D9A151` · فحمي `#403F3F` · خط Reem Kufi)

### التحويل إلى PostgreSQL
```prisma
// prisma/schema.prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```
ثم `DATABASE_URL="postgresql://user:pass@host:5432/almaqsd"` و `npx prisma db push`.

## نموذج الصلاحيات

الأدوار مطابقة لفرق الشركة المعلنة: الإداري · القانوني · الصيانة والتشغيل · المالي،
مضافاً إليها مدير النظام وبوابة المالك.

الصلاحيات معرّفة في `src/lib/roles.ts` كمصفوفة `قدرة ← أدوار مسموحة`، وتُطبَّق في
ثلاث طبقات: إخفاء عناصر القائمة، حجب الصفحة (`requirePermission`)، ورفض الإجراء
في الخادم. تعديل صلاحية واحد يسري على الطبقات الثلاث.

## قرارات تصميمية مقصودة

1. **كشف الحساب يُحتسب لحظياً، لا يُخزَّن.** أي تصحيح في سند قبض أو مصروف ينعكس فوراً
   على كشف المالك وبوابته. التوريد وحده يُخزَّن كسجل تاريخي عند اعتماده.
2. **التحصيل على أساس نقدي لا استحقاقي.** عمولة الإدارة تُحتسب على المحصّل فعلياً —
   الأعدل للطرفين والأكثر شيوعاً في عقود إدارة الأملاك.
3. **سقف الصرف يُطبَّق آلياً.** أي مصروف يتجاوز سقف عقد الإدارة يُحفظ «معلّقاً»
   بانتظار الاعتماد بدل أن يُحمّل على المالك مباشرة.
4. **الفواتير تُولَّد من العقد لا يدوياً.** يمنع الاختلاف بين ما في العقد وما يُطالب به.
