# نظام أتمتة الحملات التسويقية — شركة المقصد

نظام واحد يدير دورة الحملة كاملة: **تخطيط ← توليد محتوى ← موافقة بشرية ← نشر ← إعلانات ← التقاط عملاء ← متابعة آلية ← قياس ← قرارات تحسين**.

بُني بحيث يعمل **من اليوم الأول بلا أي حسابات إعلانية**: أي قناة تنقصها المفاتيح تعمل في وضع المحاكاة وتُسجّل ما كانت ستفعله، ويكفي إضافة المفتاح لاحقًا لتتحول إلى تنفيذ فعلي دون تغيير سطر واحد.

---

## 1. دورة اليوم الواحد

```
07:00  توليد محتوى المنشورات المستحقة (Claude) → مسودات جاهزة
08:00  طلب موافقة واحد على واتساب يضم كل منشورات اليوم
       ← ترد: موافق A001 / موافق الكل / رفض A001 / تعديل A001 ملاحظتك
كل 10د  نشر ما اعتُمد وحان موعده (لينكدإن وإنستقرام آليًا، تيك توك وسناب تُسلَّم جاهزة)
كل 15د  تنفيذ خطوات متابعة العملاء المحتملين (واتساب وبريد)
كل 30د  إنذار عند تجاوز مهلة الرد الأول (ساعتان)
06:00  سحب أرقام الإعلانات من المنصات
07:30  محرك التحسين: إيقاف الخاسر وخفض ميزانية الضعيف
21:30  تقرير يومي على واتساب والبريد
الأحد   تقرير أسبوعي
```

**لا شيء يُنشر بلا موافقتك.** ما لا يُعتمد خلال 36 ساعة يسقط تلقائيًا ولا يُنشر متأخرًا.

## 2. التشغيل

```bash
cd automation
npm install
cp .env.example .env          # املأ ما لديك، واترك الباقي فارغًا
npm run seed                  # يبني تقويم 12 أسبوعًا (156 منشورًا)
npm run dev                   # أو: docker compose up -d
```

الوضع الافتراضي `DRY_RUN=true` — يولّد ويجدول ويقرر بلا نشر أو إنفاق فعلي. اجعله `false` عند الإطلاق.

### أوامر التشغيل اليدوي

```bash
npm run cli status              # ملخص الحالة
npm run cli plan:show 30        # جدول المنشورات القادم
npm run cli content:generate    # توليد المحتوى المستحق
npm run cli approvals:digest    # إرسال طلب الموافقة
npm run cli publish:due         # نشر المعتمد
npm run cli ads:plan            # خطة الحملات والميزانيات
npm run cli ads:provision       # إنشاء الحملات
npm run cli ads:optimize        # تشغيل قواعد إيقاف الخسارة
npm run cli report:daily        # التقرير اليومي
```

## 3. أوامر واتساب (تدير النظام كله من جوالك)

| الأمر | الأثر |
|---|---|
| `موافق A001` | اعتماد منشور واحد |
| `موافق الكل` | اعتماد كل ما ينتظر |
| `رفض A001 السبب` | إلغاء المنشور نهائيًا |
| `تعديل A001 ملاحظتك` | إعادة كتابته وفق ملاحظتك ثم عرضه مجددًا |
| `عرض A001` | قراءة النص كاملًا قبل القرار |
| `حالة` | ملخص حالة المحتوى |
| `تقرير` | التقرير اليومي فورًا |
| `ربط لينكدإن <معرّف> <اسم الحملة>` | ربط حملة أُنشئت يدويًا بالنظام |
| `قياس <معرّف> <إنفاق> <ظهور> <نقرات> <عملاء>` | إدخال أرقام منصة لا تُقرأ آليًا |

## 4. ما يُنفَّذ آليًا وما يحتاج يدًا بشرية

| المهمة | الحالة | السبب |
|---|---|---|
| توليد المحتوى | **آلي** | Claude + قواعد الهوية والمحظورات |
| النشر على لينكدإن | **آلي** | واجهة النشر متاحة |
| النشر على إنستقرام | **آلي** بشرط رابط وسيط | إنستقرام لا ينشر نصًا بلا صورة أو فيديو |
| النشر على تيك توك وسناب | **يدوي بتسليم آلي** | تيك توك يشترط رفع ملف فيديو باعتماد خاص، وسناب لا يوفّر واجهة نشر عضوي — يصلك المحتوى جاهزًا في موعده |
| إنشاء حملات ميتا | **آلي** (تبدأ متوقفة) | لا إنفاق قبل قرار بشري |
| إنشاء حملات لينكدإن وتيك توك وسناب | **يدوي مرة واحدة** | تحتاج تصاميم معتمدة مسبقًا؛ بعد الربط تصبح المتابعة والإيقاف آليين |
| قراءة الأرقام | **آلي** لميتا ولينكدإن · يدوي لتيك توك وسناب | حدود الواجهات |
| قواعد إيقاف الخسارة | **آلي** | محرك التحسين |
| متابعة العملاء المحتملين | **آلي** | مسارات واتساب والبريد |
| اعتماد المحتوى | **بشري** | قرارك أنت |

## 5. البنية

```
automation/
├─ config/
│  ├─ campaign.yaml     الشرائح، القنوات، الميزانية، قواعد الإيقاف، التأهيل
│  └─ plan.yaml         تقويم 12 أسبوعًا ونسب أنواع المحتوى
└─ src/
   ├─ content/          المخطِّط، المولّد (Claude)، قواعد الهوية، خط الأنابيب
   ├─ channels/         ناشرو لينكدإن وإنستقرام + التسليم اليدوي
   ├─ ads/              خطة الحملات، ميتا، لينكدإن، محرك التحسين
   ├─ leads/            التأهيل بالنقاط وخط أنابيب العميل المحتمل
   ├─ messaging/        واتساب، بريد، مسارات المتابعة
   ├─ approvals/        طلب الموافقة ومعالجة الردود
   ├─ reports/          التقارير اليومية والأسبوعية
   ├─ scheduler/        المهام المجدولة
   └─ server.ts         الويب هوك: صفحة الهبوط، واتساب، عملاء ميتا
```

**كل ما يتغيّر بتغيّر السوق موجود في `config/` لا في الكود:** الميزانية، الشرائح، الرسائل، عدد المنشورات، قواعد الإيقاف، أوزان التأهيل.

## 6. الويب هوك

| المسار | الاستخدام |
|---|---|
| `POST /webhooks/lead` | نموذج صفحة الهبوط (يتطلب ترويسة `x-webhook-secret`) |
| `POST /webhooks/meta-leads` | نماذج إعلانات ميتا |
| `GET/POST /webhooks/whatsapp` | تحقق واتساب والرسائل الواردة |
| `GET /health` | حالة النظام وعدّاداته |

ربط صفحة الهبوط:

```js
await fetch("https://your-domain.com/webhooks/lead", {
  method: "POST",
  headers: { "Content-Type": "application/json", "x-webhook-secret": "..." },
  body: JSON.stringify({ name, phone, type, units, city, source: "landing" }),
});
```

## 7. تأهيل العميل المحتمل

يُحتسب لكل عميل عدد نقاط من: عدد الوحدات + نوع العقار + مصدره + توفّر بريده. **60 نقطة = مؤهل، 80 = ساخن.** يصلك تنبيه فوري على واتساب ببطاقته كاملة، ويبدأ مساره تلقائيًا:

- **مسار الملاك** (5 رسائل خلال 14 يومًا): تأكيد فوري ← تسليم التقرير بعد 48 ساعة ← رسالتا بريد ← تذكير أخير.
- **مسار الشراكات** (3 رسائل خلال 10 أيام): نموذجا الشراكة ← مسار العمل ← عرض بدء الدراسة.

المسار يتوقف تلقائيًا عند التعاقد أو الإغلاق، وعند أول رد من العميل تتغيّر حالته إلى «مؤهل».

## 8. قواعد إيقاف الخسارة (تعمل يوميًا)

1. إعلان أنفق **500 ريال** بلا عميل محتمل واحد → يُوقف.
2. إعلان تجاوزت تكلفة عميله **ضعف** متوسط منصته بعد 7 أيام → يُوقف.
3. منصة بلا عميل محتمل خلال **30 يومًا** → تُخفَّض ميزانيتها **70%**.
4. لا تُرفع ميزانية إعلان أكثر من **20% كل 3 أيام** (تفاديًا لإعادة مرحلة التعلّم).
5. لا تُقسَّم ميزانية منصة إلى حملات دون حدها الأدنى اليومي — يُقلَّص عدد الحملات بدل إضعافها جميعًا.

كل قرار يصلك على واتساب بسببه، ويُسجَّل في قاعدة البيانات.

## 9. المفاتيح المطلوبة بالترتيب

| الأولوية | المفتاح | يفتح |
|---|---|---|
| 1 | `ANTHROPIC_API_KEY` | توليد المحتوى فعليًا بدل المسودات البديلة |
| 2 | `WHATSAPP_*` | الموافقات والتنبيهات والمتابعة والتقارير |
| 3 | `META_*` | النشر على إنستقرام وإدارة إعلانات ميتا وقراءة أرقامها |
| 4 | `LINKEDIN_*` | النشر على لينكدإن وقراءة تحليلات إعلاناته |
| 5 | `SMTP_*` | رسائل البريد في مسارات المتابعة والتقارير |

بدون أي منها يظل النظام يعمل ويخطط ويقرر — لكنه يحاكي التنفيذ بدل تنفيذه.
